# Acceleration Ninja indirect callback connected

An isolated Dolphin JIT64 GG4E run staged two `pl0004` actors. Both live actor `+0x4d8` pointers were `0x8016234c`. The original executable's table at `0x8034c720` contains `0x80162388`, `0x8016238c`, `0x801623c0`; the last target is the already ported weapon-allocation/effect handler. The executable's `0x8034cfce` stream instruction is `[0x11, 0, 2, 0]`, following the part-0 animation-relative wait to frame 9 in family bank `0x8034cc80`, group 2 slot 0. That stream's earlier command is the grounded neutral B Shot row beginning at `0x8034ca18`.

The bridge previously dropped both this opcode in its predecoded schedule and the family callback. The bounded `pl0004` neutral B Shot path now enters the existing source family action, schedules this one evidenced callback with the source part mask, and dispatches selector 2 to the existing `accelerationNinjaChargeArm` using the real Battle weapon allocator. Only this confirmed command/stream is added; other families and selectors are unchanged. The current decoded scheduler uses a host frame approximation for the source animation-relative wait, not source-clock parity. The source `0x80099e70` effect triggers are not projectile constructors: production no longer turns these Acceleration Ninja triggers into generic damaging shots. Their authored visual effects are still unimplemented.

A real Battle input test presses B, reaches the source action, consumes one explicitly configured weapon charge, and creates no fake projectile. Separate bridge tests cover allocation success and denial, effect trigger order, and suppression when part 0 is masked out. The full ROM suite and combat TypeScript build passed. This is not a full original-game move, physics, effect-visual, or hardware parity claim. The dedicated emulator was stopped; the pre-existing unrelated Dolphin instance was left running.
