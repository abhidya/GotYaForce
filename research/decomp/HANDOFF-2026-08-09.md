## 4. THE DESIGN (owner direction + research-mapped)

**Trunk:** compiled ROM code becomes the logic engine; TS is the platform layer.
The existing hand-built renderer/audio/input (battleScene three.js, HUD, packages/
audio) is our libultraship/RT64-equivalent — renderer-first requirement already met.

**Owner's core directive: pure Ghidra → ported code, no human per unit.**
Port the decompiled C 1:1 into compilable modules (emcc → wasm) with ORIGINAL
function names as exports, loaded from TS. The LLM's job collapses from "translate
semantics" (failure-prone) to "make this C compile" (compiler-gated, objective,
local; LLM4Decompile finding: refine-to-reexecutable beats end-to-end by >100%).

Pipeline stages (mechanical except stage 3):
1. **SDK classification pass** — `gnt4_PSVEC*/GX*/OS*/HSD*/TRK*/DVD*` etc. are NEVER
   ported; mapped to TS shim imports (removes est. 20-40% of 11,980 fns).
2. **Header + arena generation** (deterministic tool): prototypes for all functions
   from `_index.tsv`; every `DAT_/FLOAT_/PTR_` global declared into one memory arena
   at original addresses; ROM tables emitted as C from existing `gen-*.mjs` data.
3. **Per-unit compile loop** (the ONLY LLM stage): emcc compile → exact compiler
   error fed back → fix → repeat until link. Auto-stub + log unresolved imports.
4. **Oracle gate**: same inputs into wasm unit and a known-good reference (existing
   TS ports: sourceDamage/knockback/challengeFlowVm; later Dolphin traces);
   programmatic output diff. NEVER trust model claims of correctness (§7 Chromatron).
5. **Commit per green unit; external difficulty scorer picks next** from the
   game-gap queue (§2 gaps), not chunk order.

Known gotchas + standard fixes: PowerPC big-endian (convert extracted tables at
generation time — extractors already control byte order); float-bit reinterpret
tricks (compile fine in C; TS translation kept mangling them); common header set
built once from findings docs (actor struct offsets etc.); `PTR_FUN_*` dispatch
tables work natively in C; wasm little-endian only matters at data boundaries.

## 5. THE POC (valid = proves the RISKY path end-to-end, zero human decisions)

Research verdict: CPU-code translation is the known-easy part; the unproven parts
are (a) automated compile-fix convergence cost and (b) the seam into the running
browser game. The POC crosses both:

- **Unit A (oracle-rich pure logic):** damage-formula functions (chunk_0004;
  exact addresses in `attack-mechanics-findings.md` formula steps §ah,
  chunk_0004.c:6693+). Ghidra C → scaffold → compile loop → wasm. Drive wasm AND
  `packages/combat/src/damage/sourceDamage.ts` with the same recorded input corpus;
  **byte-diff outputs**.
- **Unit B (SDK seam):** one function calling `gnt4_PSVEC*` math → shim imports in
  TS → link → run. Proves the boundary that decides scaling.
- **Loaded in the actual browser app** via the smoke harness (extend
  `scripts/smoke-browser-game.mjs` to drive `window.__gf`), not a node bench.

**Pass:** corpus outputs match oracle (float diffs eliminated or explained);
compile-fix converged with zero semantic/human edits; shims linked; runs in-browser.
**Fail (kill criteria, record and stop):** loop needs semantic edits to converge, or
float determinism unachievable.
**Metrics that decide go/no-go for the remaining logic layer:** compile-fix
iterations/unit (scaling cost), % output parity (fidelity), shim-calls/unit (seam
load). Optionally run the compile loop twice (35B vs untried 27B) for the model-tier
answer in the same POC.
