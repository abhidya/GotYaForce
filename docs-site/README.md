# Gotcha Force Research Atlas

Static site (VitePress + Vue) deployed to GitHub Pages at
**https://abhidya.github.io/GotYaForce/**.

All data is curated from `research/` source files — no hand-written JSON.

Contributor-facing setup, verification, porting, asset, and troubleshooting
workflows are published under [`contributing/`](contributing/index.md). This
file documents atlas maintenance details; the contributor pages are the
browsable entry point.

## Local dev

```bash
cd docs-site
pnpm install
node ../docs-site/scripts/curate-data.mjs   # regenerate data from research/
pnpm dev
```

The curate step also copies extracted Borg model and animation assets from
`apps/game/public/models` into `docs-site/public/models` so Borg detail pages can
render the real GLB and baked animation clips. For text/data-only local work, run
with `GF_ATLAS_SKIP_MODELS=1` to skip that heavier asset copy.

The build step runs a second explicit sync from `docs-site/public/models` into
`.vitepress/dist/models`. This catches large generated model folders that
VitePress may not copy through the normal public-asset path.

## Build

```bash
node scripts/curate-data.mjs   # reads research/, writes .vitepress/data/*.json
pnpm build                     # outputs .vitepress/dist/
```

## Data flow

```
research/**/*.json  ──┐
research/**/*.md    ──┼──► scripts/curate-data.mjs ──► .vitepress/data/*.json
research/**/*.csv   ──┘                                       │
                                                              ▼
                                          .vitepress/theme/components/*.vue
                                                              │
                                                              ▼
                                                       VitePress build
                                                              │
                                                              ▼
                                          .vitepress/dist/  (deployed)
```

Never edit `.vitepress/data/*.json` by hand. Edit the curate script or the
upstream `research/` files, then re-run the script.

### Two outputs, one of them committed

`curate-data.mjs` writes to two places, and they are tracked differently:

| Output | Tracked? |
| --- | --- |
| `.vitepress/data/*.json` | **No** — gitignored, regenerated on every build |
| `public/chunks/*.c` (copies of `research/decomp/ghidra-export/chunk_*.c`) | **Yes** — committed |

The committed copy is the one that goes stale. On 2026-08-26 a corpus correction landed in
`research/decomp/ghidra-export/chunk_0001.c` without a re-curate, so the published atlas
served pre-correction source for three days. `.github/workflows/ci.yml` now runs
`git diff --exit-code -- docs-site/public/chunks` after `pnpm verify:docs`, which fails the
build if the copy drifts again. Re-run `pnpm atlas:curate` and commit the result after any
edit under `research/decomp/ghidra-export/`.

### Known degradation in a clean checkout

`curate-data.mjs` reads `research/decomp/organized/`, of which **only `_map.tsv` is tracked**
— the per-function `.c` files are gitignored and regenerated by
`node scripts/reorg-decomp.mjs`. The dashboard's "Decomp organized" figure is therefore
derived from the tracked map's *function* counts, not from a directory walk, so it reports
the same number on CI as it does locally. If you add a metric that walks `organized/`, expect
it to read zero on a clean clone unless the reorg script has been run first.

## GitHub Pages

Push to `main` triggers `.github/workflows/deploy-pages.yml`, which:

1. Installs docs-site deps
2. Runs `curate-data.mjs` against the checked-out `research/`
3. Builds VitePress with `GH_PAGES_BASE=/GotYaForce/`
4. Uploads `dist/` and deploys via `actions/deploy-pages`

## Adding a new page

1. Drop a `.md` file under the appropriate section folder.
2. Wire it into `.vitepress/config.ts` nav and sidebar.
3. Use the global components: `StatusBadge`, `MetricCard`, `ProgressMatrix`,
   `EvidenceCard`, `AtlasTable`, `ClaimTrail`, `HeroDashboard`.

## Adding a new data source

Edit `scripts/curate-data.mjs`. Read from `research/`, emit JSON to
`.vitepress/data/`. The build picks it up automatically.
