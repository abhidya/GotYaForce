# Roadmap

Two efforts run in parallel, and they are at very different maturities.

## 1. TypeScript recreation — playable, filling in

The hand-written game. This is what is deployed. Work is tracked per subsystem in
`research/decomp/PORT-1TO1-STATUS.md` and burned down through the TUNED ledger.

### TUNED burndown

A `TUNED` marker is a constant still awaiting ROM or trace evidence; `DERIVED` means the
evidence is cited. The recreation reaches 1:1 when the TUNED list is empty, or every
remaining entry is an intentional, documented simplification.

## 2. wasm-unit port pipeline — research-stage

Recompiling the decompiled ROM C into WebAssembly units and proving each one behaves like the
real console. The design contract is `docs/playable-port-design.md` (v5, PASS verdict).

### Read the tier, not the word "green"

| Tier | Claim |
|---|---|
| `compile_only` | Compiles and links. **Nothing about behavior.** Inventory, not progress |
| `oracle_green` | Full corpus replays byte-exact against an independent oracle |
| `boundary_green` | Callee-boundary replay for a nonterminating spine; never upgrades to `oracle_green` |
